# 任务资料 Git 同步

在 **设置 → 资料与说明 → 资料目录与浏览** 中配置资料根目录和资料子目录；在 **资料自动同步** 子页配置 Git 仓库地址，并从下拉框选择已有远程分支。分支列表支持刷新；空仓库需要先在远程创建分支。认证使用系统 Git 凭据和 SSH 配置。

自动同步默认关闭，周期默认 5 分钟，可填写正整数分钟。启用后仅在 SW 运行时执行，也可点击“立即同步”；编辑或保存仓库地址、刷新分支列表不会发起同步。修改仓库或分支后自动同步暂停，核对目标后使用“重新检查并恢复”。

新建需求资料采用“资料根目录／年份／需求编号-需求文件夹名／资料子目录”的结构，不增加 Sprint 或个人目录。创建任务时跨年份按完整编号查找，唯一匹配则沿用实际目录；重复、身份不符或读取失败时停止。旧平铺目录不会被自动迁移或用于需求目录匹配；位于所配置仓库内的文件仍按 Git 规则参与同步。

同步范围是整个资料仓库，使用原生 `git add -A` 收集既有暂存内容以及文件、附件和普通持久元数据的增删改。年度以外的目录、团队成员目录和 `temp` 均遵守用户自己的 Git 忽略规则；已被 Git 跟踪的文件仍按 Git 的跟踪语义处理，不会因为后来加入忽略规则而停止同步。SW 内的编辑权限仍仅限本人配置的资料子目录和 `temp`，其他同级目录保持只读；Git 同步范围与编辑权限分别生效。

每轮先获取并合并远程指定分支，再提交本地资料，最后推送，使最新远程忽略规则在首次上传前生效。首次将非空本地目录接入已有远程仓库时也先检出远端内容；同名文件或正常 Git 合并前置条件不满足时暂停，保留本地文件、暂存区和历史。即使冲突文件被用户忽略，也不会强行覆盖。已有仓库的源与设置不一致时停止，不自动覆盖 Git 源；无本地变更时不创建空提交。

SW 不再生成 `temp/.gitignore` 或 `.git/info/exclude` 规则；用户可以自行维护 `temp/.gitignore`。旧规则迁移仅删除带 Silverwing 标记的已知默认规则块，用户其他内容及相同但未带标记的规则逐字保留。完全由软件生成且迁移后为空的忽略文件会删除；迁移失败时先停止，不带旧默认规则继续提交。运行锁放在系统临时目录的专用目录中，按规范化的资料根路径标识，跨应用数据目录、跨进程共用。仍被旧版本占用的旧锁会阻止操作；仅清理已空闲、可识别的旧运行锁，不强行终止进程。

任务根 `AGENTS.md` 和 `TASK-CONTEXT.md` 的系统管理区只明确列出本人正式目录和临时目录的完整路径；其他同级团队目录由 AI 自行发现并主动阅读，保持只读。检出或合并后更新所有关联任务，包括归档任务。后续推送失败时也更新本地说明；自定义说明或写入失败会提示，可通过“刷新资料”单独重试说明更新，不重复同步。

未保存资料或文件操作尚未完成时会延后同步。存在 Git 冲突、未完成合并、认证或仓库身份问题时自动同步暂停；通过“打开仓库”使用 Git 或 IDE 解决冲突并提交，再回到设置中重新检查。SW 不会强推、强制重置、清理文件或自动放弃合并；网络故障在下一周期重试。

同页“默认展开目录层级”默认是 2，0 表示全部折叠。修改后当前资料树立即重新应用，其他任务下次打开时应用；之后继续保留手工展开和收起状态。
