# 配置项参考

[返回知识库目录](../Index.md) · [相关：任务与工作区数据模型](../技术架构/23-任务与工作区数据模型.md) · [相关：目录与数据存储](20-目录与数据存储.md)

本文依据 Silverwing Go / MyGO 当前配置结构整理，核对日期为 2026-10-19。产品版本 `0.0.1` 与应用配置 schema `6.0.0` 是两套版本：产品更新不等于配置 schema 自动兼容。字段名采用 JSON 名称，类型采用 Go 定义；`*string` 表示可空字段，空值通常表现为 `nil`，列表的空值是空数组。

## 使用原则

公共版管理七个配置分片，字段与分片对应关系见[配置持久化与恢复机制](../技术架构/24-配置持久化与恢复机制.md)。日常请在界面对应设置页修改。配置读取和导入按当前版本的 schema 校验；导出只包含当前 schema 管理的配置分片。`设置 → 存储 → 配置与备份 → 查看配置`会按文件名分段显示 `config/` 下可读的普通文件。原始配置可能包含代理用户名和密码，查看、复制、分享或导出时应按敏感资料处理。

不要直接编辑全部配置 JSON 后覆盖目录。设置界面提交字段级更新；更新数组会替换该数组，更新对象叶子字段会与当前对象合并。界面另对任务根目录迁移、仓库/服务配置等操作做专门校验。全量 JSON 覆盖可能丢失并发更新、破坏分片一致性或被严格 schema 校验拒绝。

> [!info] 默认值口径
> 下表中的首次默认值取自 `DefaultAppConfig` 及配置解码默认值。应用第一次初始化时会把解析后的默认任务根目录写入配置；后续以当前设置和导入预览为准。服务、模块等嵌套字段另有解码默认值，见下方结构表。来源：`internal/domain/models.go`、`internal/domain/unmarshal.go`、`internal/storage/config_store.go`。

## AppConfig 顶层字段

### 目录、仓库与项目组

| JSON 字段 | 类型 | 默认值 / 条件 | 设置入口或性质 |
| --- | --- | --- | --- |
| `schemaVersion` | `string` | `6.0.0` | 运行时 AppConfig 的 schema 标识；解码时由当前默认配置提供，七个公共分片分别存整数 `schema: 6`。不可在界面编辑。 |
| `taskRoot` | `*string` | 首次初始化解析为默认任务根目录 `~/tasks`；基础默认值为 nil | 「设置 → 存储 → 目录 → 任务根目录」。默认应用 Home `~/silverwing` 与任务根分开；改动走迁移或切换流程，不走普通字段保存。 |
| `defaultBranchPrefix` | `string` | 空字符串 | 「设置 → Git → 分支名设置 → 默认分支名规则」。可使用 `{num}`、`{ai}` 占位符。 |
| `repositories` | `[]RepositoryConfig` | 空数组 | 「服务」页面添加、移除本地仓库；Git 信息可刷新。远程、当前分支和默认远程分支由本机 Git 检测填充。 |
| `groups` | `[]GroupConfig` | 一个 `default` /「默认组」，至少保留一个组 | 「服务」页面创建、重命名、排序项目组，并管理组内服务。组 ID 由应用生成。 |

## 嵌套数据结构

这些结构决定服务如何从仓库映射到任务工作区；完整模型、任务清单和工作区关系见[任务与工作区数据模型](../技术架构/23-任务与工作区数据模型.md)。

| 结构 | 关键字段与含义 | 默认 / 派生规则 |
| --- | --- | --- |
| `RepositoryConfig` | `id` 稳定标识；`name` 名称；`rootPath` 本地仓库根路径；`gitCommonDirectory` Git 公共目录标识；`originUrl`、`currentBranch`、`defaultRemoteBranch` 为可空 Git 信息。 | 添加仓库时生成 ID 并检测 Git 信息；刷新可更新远程与分支摘要。Git 公共目录用于识别同一仓库。 |
| `GroupConfig` | `id`、`name` 标识和名称；`services` 服务列表。 | 默认组为 `default` /「默认组」。 |
| `GroupServiceConfig` | `id`；`repositoryId` 绑定仓库；`displayName` 显示名称；`enabled` 新任务是否可选；`developmentTool` 默认 IDE；`masterBranch` 服务主分支；`commitMessageTemplate` 提交模板；`modules` 模块；`bootstrap` 初始化规则。 | 解码时服务默认启用、默认 IDE 为 IntelliJ IDEA；模块缺失时补一个默认模块。 |
| `ServiceModuleConfig` | `id`、`name`；`masterBranch` 可空，控制是否继承服务主分支；`strategy` 工作区策略；`customCommands` 工作区快捷命令。 | 默认名 `default`，策略 `STANDARD_WORKTREE`。分支为空时继承服务主分支；策略还可选 `INDEPENDENT_CLONE`。 |
| `BootstrapConfig` | `copyRules` 从原仓库复制文件或目录；`commands` 创建工作区时运行初始化命令。复制路径必须是仓库内相对路径，命令在目标工作区执行。 | 复制目标缺省为源路径，`overwrite` 默认 true；初始化命令参数默认为空数组、工作目录 `.`、超时 600 秒、启用。服务配置的「复制规则」「初始化命令」页编辑。 |
| `WorkspaceCommandConfig` | `id`、`name`、`iconKey`、`executable`、`arguments`、`workingDirectory`、`timeoutSeconds`、`enabled`。参数按数组传递，不经过 Shell；命令配置在模块快捷命令里。 | 图标 `build`、参数空数组、目录 `.`、超时 1800 秒、启用。 |
| `MeegleProjectConfig` | `project_key` 项目空间 Key；`simple_name` 便于界面识别的短名。 | Key 和短名必填且只能使用字母、数字、下划线、连字符；项目 Key 唯一。 |
| `CodexPluginMarketplaceSource` / `SkillSource` | 共同字段：`id`、`name`、`repositoryUrl`、`ref`；Marketplace 另有 `marketplaceDirectory`，Skill 来源另有 `skillRoot`。 | `ref`、`skillRoot` 可空；Marketplace 目录缺省为 `plugins`。仓库地址和子目录由来源管理界面校验。 |

## 示例与排错

例如需要保护团队主分支时，在「设置 → Git → Git 配置 → 分支写保护」添加实际分支名；需要把启动代理仅用于 Codex 时，在「设置 → 代理」选中 Codex CLI，保存后通过该页测试。修改服务主分支时进入「服务 → 选择项目组 → 服务行「配置」→ Git → 主分支」，模块可单独覆盖或继承；不要只改一个工作区的生成记录来代替服务配置。

遇到导入校验失败，先核对导出 ZIP 是否来自当前可识别的配置 schema，并确认公共字段可读。遇到 CLI 路径无法运行，打开对应 CLI 设置页刷新状态；自动检测状态和持久化路径不是一回事。配置预览、自动备份和恢复范围见[配置持久化与恢复机制](../技术架构/24-配置持久化与恢复机制.md)。
