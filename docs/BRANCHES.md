# Silverwing 分支与功能边界

本仓库使用两个长期分支维护公共版和 SNB 内部版：

| 分支 | 定位 |
| --- | --- |
| `master` | 公共版，保留通用任务、需求、资料、Git 工作区、差异审阅和集成能力。 |
| `release/snb` | SNB 内部版，在公共能力之上维护内部产品集成和发布工作流。 |

两个分支都位于同一个公开 GitHub 仓库，分支名只区分功能版本，不提供代码保密。本次提交历史整理后，`master` 以当前公共版源码作为首次提交；`release/snb` 基于该提交，再用一个提交增加内部功能。

## 功能归属

Git 状态的进程内缓存、任务切换时的平滑展示，以及 Git 刷新失败后保留上次有效结果并提示，属于公共能力，先进入 `master`，再同步到 `release/snb`。确认弹窗、为生产发布增加的差异预览组件和生产发布进度通知等当前界面扩展，仅进入 `release/snb`。

全部任务 Tag 功能、Genbu 集成和生产发布工作流仅在 `release/snb`。公共版不提供这些功能入口或执行逻辑。两版按各自当前 schema 读写配置与任务清单；不支持跨版共用配置、导入对方版本的数据或保证跨版数据兼容。分支切换不会自动删除本机文件、Git 历史或工作区。

## 后续同步规则

- 公共修复和功能先进入 `master`，验证后再合并/同步到 `release/snb`。
- 内部功能在 `release/snb` 开发并仅回合该分支；不把整个内部分支反向合并到 `master`。
- 同步时吸收 `master` 的公共更新，并在 `release/snb` 保留其内部实现。
- 当前功能边界说明不代表新增产品版本、安装包或 Git Release。
