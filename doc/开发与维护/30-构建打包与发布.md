## 先分清编译产物和可交付包

在仓库根目录、Go 1.27.1 和当前 Go 开发主机上执行 `go build ./cmd/silverwing`，得到的是面向当前操作系统的可执行文件。它包含 Go 程序本身，但不会自动下载并摆放 PDFium、Mermaid 渲染器及第三方授权文件；本地开发可直接用 `go run ./cmd/silverwing`，而“编译成功”不等于 portable 包已具备完整媒体资源。

Windows 的 portable 包由 `scripts/build-windows.ps1 -PortableOnly` 构建。脚本会编译 Windows x64 GUI，准备固定版本的 `resources/`、授权 notices 和运行时文件，并生成可解压运行的 ZIP。它不安装应用、不写系统安装信息，也不发布到远端。完整脚本还能生成按用户安装的 Setup EXE 和 MSI；这两种安装包需要 NSIS 3.13 与 WiX Toolset 3.14.1，脚本可使用便携工具路径，工具链只用于构建，运行应用不需要预装。

当前 macOS 打包脚本仅面向 Apple silicon（arm64）。在该平台安装 Go 1.27.1、Xcode Command Line Tools，并具备 `codesign`、`plutil` 和 `hdiutil` 后，运行 `bash ./scripts/build-macos.sh` 会生成 `Silverwing.app` 与压缩 DMG。App 使用 ad-hoc 签名用于本机完整性检查，没有 Developer ID 签名或公证；下载后仍可能看到 Gatekeeper 提示。脚本不产出 Intel 或 Universal 包，项目当前也未提供 Linux、Windows ARM 发行包。

构建脚本从 `domain.CurrentProductVersion` 读取产品版本，并以 linker flags 写入版本、提交号和构建时间。它将 PDFium 与 mmdr 的归档按 SHA-256 校验后放入应用资源目录，并收集 Go 依赖许可证；缺少必须的资源、校验不符或许可证时构建会失败。平台目录结构、固定版本和完整命令见 [`../../docs/RELEASE.md`](../../docs/RELEASE.md)。

## 本地构建示例

在 Windows PowerShell、Windows x64 环境和 Go 1.27.1 下，只想验证 portable 包时：

```powershell
.\scripts\build-windows.ps1 -PortableOnly
```

该脚本需要下载或复用校验通过的固定资源，因此须能访问发行说明列出的来源。完整构建会同时输出 ZIP、Setup EXE 与 MSI，并检查 NSIS、WiX 版本。构建目录位于忽略的 `build/native-release/` 下；脚本为每次执行创建带版本与 UTC 时间的新目录，不覆盖已有输出。

在 Apple silicon Mac 上使用发行包脚本：

```bash
bash ./scripts/build-macos.sh
```

它在 `build/native-release/macos-arm64/` 下创建唯一输出目录。上述本地命令只生成本机文件，不触发 GitHub 发布，也不等于完成安装、真实账号登录或跨平台运行验收。

## CI artifact 与正式 Release

`.github/workflows/native-build.yml` 在分支推送、PR 和手动运行时执行版本检查及两个平台的常规构建：Windows x64 portable ZIP 和 macOS arm64 DMG。Actions 将它们作为普通 workflow artifact 保存 14 天，供这次运行下载核对；它们不是带长期版本页面的正式发行资产。

推送 `v*` 标签时，CI 要求标签严格等于 `v` 加源码中的 `CurrentProductVersion`。两端构建全部成功后，发布脚本检查完整资产集合：Windows portable ZIP、Setup EXE、MSI，以及 macOS arm64 DMG；随后上传 draft 并发布 GitHub Release。只有指定仓库的 release job 获得 contents 写权限。普通分支、PR 或手动构建不会替代这个标签发布流程。

发布行为会创建并公开远端发行记录，本文只说明流程，不在本地调试中运行发布脚本。遇到失败时先看 workflow 的版本校验、资源 SHA-256、许可证收集和资产数量检查，再按 [`../../docs/RELEASE.md`](../../docs/RELEASE.md) 的平台章节定位；不要把普通 artifact 的存在描述成 Release 已发布。

## 源码入口

- Windows 资源准备、portable 与安装包：`scripts/build-windows.ps1`
- macOS arm64 app 与 DMG：`scripts/build-macos.sh`
- Actions 构建和标签发布条件：`.github/workflows/native-build.yml`
- Release 资产校验及发布：`scripts/publish-release.py`
- 版本元数据与资源路径：`internal/buildinfo/buildinfo.go`
