# 生产发布

“生产发布”位于独立侧栏，使用已启用服务的仓库和服务级主分支配置。全局 Tag 开关同时控制该入口。每个仓库只允许一个进行中批次，批次独立于任务测试 Tag 历史。

服务列表只显示一行“项目组 · 项目名”；全部服务属于一个项目组时只显示项目名，搜索不会改变分组显示方式。仓库、主分支和路径移入悬停提示，仍支持按这些内容搜索；生产操作确认窗口默认展示服务、来源和目标的短提交号、仓库路径及远端，完整身份移入“详细信息”。

## 创建与追加

1. **对比生产 Tag 与主分支差异**：在内容区并排提供“重新检查”和差异入口。检查 Genbu 生产 Pod 的运行版本及远端 Git Tag，没有待合入文件变化时显示“无差异”，有变化时显示黄色“查看差异”，仍可打开文件对比弹窗及双方独有提交记录。初始化结果始终展开，完成后也保留步骤 1–3 与检查、差异入口，不提供展开或收起按钮；已结束批次的入口位于批次信息下方。成功状态使用绿色，基线卡不再重复展示流水线生产发布状态或“差异已就绪”提示。
2. **合并生产 Tag 到主分支**：将生产 Tag 合入服务主分支并推送，保留主分支已有全部代码；已包含的提交跳过。
3. **创建 release 分支**：从同步后的主分支创建并推送 `release/2.3.44`。输入框自动填入完整分支名，例如 `release/2.3.44`；可修改版本部分。未手工编辑时重新检查会更新建议，已编辑时保留输入。每次点击并确认只执行本项及其推送，不会顺带执行其他合并或创建。创建完成后继续显示结果。
4. **合并 feature 分支**：在带标签、边框与箭头的搜索下拉框中，每次选择或填写一个远端分支，用 `--no-ff` 合入明确标出的 release 并推送。字段最大宽度 560 逻辑像素，窄窗口将操作按钮移到下一行；长分支名可通过悬停查看。新预检确认已包含时，只在此区域提示“已包含，无需合并”，不弹出无效的合并确认；切换分支清除旧提示。同一分支新增提交后可以再次预检与合并。
5. **构建时自动检查**：不单独显示检查区和检查按钮。点击“构建 Tag”后自动重新读取线上版本、Git 引用及包含关系，准备阶段只读取 Git，不执行合并或推送。只有确实缺少同步时，才在构建区显示对应的主分支／release 合并入口；每次合并仍需独立确认，完成后再次点击构建。上次显示没有新增提交也不代替本轮远端检查。
6. **构建生产 Tag**：自动检查通过后展示本轮最终 release 提交、差异和建议 Tag，并弹出原生确认窗口；用户确认后推送 annotated Tag 并跟踪构建结果。取消确认后可继续合并分支或重新发起构建，新合并会使旧构建准备失效。切换页面后准备继续完成，但不会在其它页面自动弹出确认或执行写入。

初始化后显示“合并分支”和“构建生产 Tag”两个操作区，内容最大宽度 1080 逻辑像素。需要同步时，构建区按生产 Tag → 主分支、主分支 → 当前 release 的实际缺失关系分别显示状态、差异和合并操作，已经包含的关系不重复列出。可以连续合并多个 feature 后构建，也可以多轮合并、构建。生产基线、主分支或 release 变化时旧构建确认立即失效。累计分支记录默认收起，展开后在限高区域滚动查看。构建完成后留在当前批次，只有用户在批次“更多”菜单中确认“结束批次”才结束；已有分支和 Tag 不会使入口消失。历史批次默认折叠，排除当前正在查看的批次；最近一个 Tag 的构建状态直接可见，之前的 Tag 可展开查看。重复选择已经包含的分支不清除有效构建准备；实际新增合并才使旧准备失效。前一个 Tag 等待构建时仍可追加分支，各 Tag 状态独立保存，旧的未完成构建仍继续跟踪。

运行进度及取消操作使用现有底部原生提示框，不占用页面布局；进度阶段更新复用同一个提示，结束或上下文失效后自动移除。切页或同时操作多个服务时标明所属服务，取消仅绑定原请求；自动 Tag 状态探测静默更新，手动刷新仍显示进度。错误与恢复入口保留在发起操作的区域，不在页头或批次中重复显示同一消息。合并后的自动读取仍归属本次合并；已确认成功后读取失败显示“合并已完成，状态刷新失败”，保留已保存的合并结果。局部提示仅保存在进程内，绑定服务、批次、分支、完整提交号及请求代次；不会作为写入授权或绕过仓库校验。

生产写入确认窗口打开时暂缓后台 Tag 状态探测，关闭后继续跟踪，避免自动读取抢占互斥入口导致已确认操作被忽略。

多版本混跑或查询不可用时，从标题右侧“更多 → 手动确认生产 Tag”打开独立窗口，搜索或填写远端存在的 Tag，再应用并重新检查；也可恢复自动识别。取消和 Esc 不改变基线。下拉列表按 Git 创建时间降序；annotated Tag 使用自身时间，轻量 Tag 使用目标提交时间；同时间按名称升序，时间缺失放末尾。时间读取失败明确提示，版本计算仍按数字规则。

基础版本从远端三段／四段正式数字 Tag 的最大值计算，第三段加一，忽略 beta 等非正式格式。例如 `2.3.43.2 → 2.3.44`。创建前可改为更大且未占用的三段版本。生产流程的主分支写入仍需专用确认，不修改全局写保护。

首次需要合入有新增提交的功能分支。之后按 `2.3.44 → 2.3.44.1 → 2.3.44.2` 续号，参考远端已占用的序号。最终 release HEAD 与上次已推送 Tag 的目标提交一致时不生成新 Tag；构建失败到平台重新编译，再刷新同一个 Tag 的构建状态。正式部署继续走现有发布平台。

手工基线只对已检查并确认的线上版本集合有效；混跑版本或查询可用性变化后，需要重新检查。相关配置失效时，在写入新待办或采用远端结果之前拒绝操作；构建状态查询期间配置变化也不会保存迟到结果。

## 冲突和恢复

冲突时保留专用工作区并打开服务配置的 IDE。用户解决冲突并完成 merge commit，返回 SW 点击“校验并继续”。SW 校验工作区身份、未提交改动、合并状态以及源和目标提交包含关系后推送。用户已自行推送且结果一致时，直接确认完成。

远端新增提交会暂停原操作。“核对远端变化”展示差异，确认后才能基于新远端继续；原工作区保留。远端改写原历史时拒绝自动恢复。Tag 编号被占用时不覆盖，先核实旧推送结果，再重新准备编号和生产基线。

中断后的合并在继续之前重新核对线上基线。主分支合并期间基线变化时，可重新检查并主动“重新确认生产基线并合并主分支”；保留原工作区，仅执行这一次合并。其他待处理合并的旧基线失效时暂停，保留现场供核对或结束批次。旧版本保存的连续操作恢复后也只完成当前步骤，后续由用户点击。

分支推送以预期提交作原子比较。已有分支的结果必须包含原目标历史；创建分支要求远端仍不存在。检查后发生的回退或抢先创建也会拒绝，不改写远端历史。

切换页面不会中止后台操作。关闭应用会取消并清理进程，保留磁盘上的批次及冲突工作区；重启后由用户主动继续。网络报错不等于远端写入失败，恢复时首先核实实际分支和 Tag 对象，避免重复执行。主分支同步成功、release 尚未创建时也保存初始化记录；版本在点击创建 release 时确定，重启后可继续。

批次记录位于应用 Home 的 `production-releases/`，采用现有 Schema 1 的逐批次 JSON，兼容未确定版本的初始化阶段 与原子写入。隔离工作区位于 `production-worktrees/`，Git 引用保存在 `refs/silverwing/production/` 以及私有工作分支中，不替换用户本地分支和 Tag。相关配置或远端身份变化会使原确认失效。

“结束批次”保留远端分支、Tag、历史和未完成工作区。按照团队流程，同一个服务不存在更高基础版本抢先上线的情况，不增加跨基础版本的自动迁移规则。

已结束批次可通过右上角“更多 → 删除批次”删除本地记录，确认默认聚焦取消。此操作只移除对应 `production-releases/<批次 ID>.json`，保留全部工作区、手工修改、远端分支、Tag 和任务测试 Tag 历史；不需要连接 Git 或 Genbu。进行中批次不提供删除入口。确认绑定完整记录摘要，记录更新或同 ID 重建时拒绝旧操作；删除失败保留记录。成功后清理该批次的本地视图和探测定时器，迟到的列表或状态结果不能恢复已删除记录。

原服务被停用、移除或调整分组后，已有批次仍以“历史”服务显示，使用保存的仓库路径。可以查看记录或手工结束批次；后台不会自动恢复远端写入，继续操作仍需通过当前配置校验。

结束时未确认的 Tag、合并提交及工作区仍显示在批次历史。“核对远端结果”只记录已经存在的结果，不执行合并、创建或推送；配置失效或远端不可用时保留待确认记录。保留工作区可在配置校验通过后打开。已确认的 Tag 仍可刷新构建状态。

## 界面设计约定

这是现有 MyGO 桌面的操作型扩展，沿用 `theme.go` 的明暗主题、系统字体、蓝色主按钮、原生更多菜单、对话框和可搜索单选下拉框。左侧紧凑服务选择，右侧为始终展开的初始化结果、可重复执行的 4–6 步及历史。确认窗口用于展示真实远端、提交范围与写入目标；冲突在对应步骤直接给出工作区、文件和恢复入口。

界面绘制只消费内存状态；磁盘、Git、Genbu 和 IDE 调用都由可取消的后台请求执行。选择任务、草稿、最近访问和任务测试 Tag 不参与生产发布状态。

开发验证使用标明 synthetic／示例的本地 Git 裸仓库和 Genbu 替身。操作层级的明暗主题、960／1440 渲染图与回归证据在 `build/production-hierarchy-20261021/` 下；此前确认弹窗和工作流证据见 `build/production-summary-20261021/` 与 `build/production-manual-20261021/`。这些渲染图不代表真实生产发布验收。

## 确认与包含状态

生产确认弹窗统一使用摘要与折叠详情：默认显示服务、来源、目标、仓库路径和远端；项目组 ID、仓库 ID、完整 SHA、提交记录和差异文本默认收起，可展开、选择和复制。保留历史、工作区和远端写入等必要提示直接可见，取消保留默认焦点。展示和展开详情不会改变已确认的完整参数；服务、批次、手工基线、Home 或相关配置变化后拒绝旧确认。

有效检查结果确认生产 Tag → 主分支、主分支 → release 的包含关系后，显示清晰的“无需合并”状态和说明，移除相应灰色按钮。没有结果时不推断为已包含，重新检查时可继续展示上次有效结果。

## 差异弹窗

生产基线、feature、主分支到 release 以及本次 Tag 构建均使用同一原生弹窗。左侧复用任务详情的目录／文件列表，右侧复用其代码对比和有界预览，另有“提交记录”页。源、目标引用和完整 SHA 固定展示；合并预览显示合并基点到源提交的待合入变更，提交记录 `<` 为目标独有、`>` 为源独有；构建预览显示上次 Tag（首次为 release 初始提交）到最终 release 的变化。

文件读取只使用固定提交对象，不读取任务草稿或用户工作区未提交文件，不创建临时分支、索引或执行 fetch。文件切换有独立取消与请求代次保护；关闭、Esc、切换服务／批次、数据目录或配置变化后拒绝迟到结果。界面、读取任务和缓存不占用任务详情的选择与阅读状态。
