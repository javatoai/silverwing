# Silverwing 分支与功能边界

本仓库使用四个长期分支维护公共版及 SNB 研发、测试和产品版本：

| 分支 | 应用名 | 定位与更新渠道 |
| --- | --- | --- |
| `master` | `silverwing` | 公共版，保留通用任务、需求、资料、Git 工作区、差异审阅和集成能力。 |
| `release/snb-dev` | `silverwing` | SNB 研发版，在公共能力之上维护内部产品集成和发布工作流，继续使用 `vX.Y.Z` 标签及研发版更新渠道。 |
| `release/snb-qa` | `silverwing-qa` | 面向测试同事，保留任务、需求、资料与 AI 能力，使用 `qa-vX.Y.Z` 标签和 `silverwing-qa-*` 安装包。 |
| `release/snb-product` | `silverwing-product` | 面向产品同事，功能与 QA 版一致，使用 `product-vX.Y.Z` 标签和 `silverwing-product-*` 安装包。 |

这些分支都位于同一个公开 GitHub 仓库，分支名只区分功能版本，不提供代码保密。历史整理时，`master` 以当时的公共版源码作为首次提交；研发分支在其基础上增加内部功能。QA 版从研发版已提交的 `23fa44b` 基线裁剪而来；产品版直接从完成的 QA 代码派生，之后分别维护和同步适用修复。

## 功能归属

Git 状态的进程内缓存、任务切换时的平滑展示，以及 Git 刷新失败后保留上次有效结果并提示，属于公共能力，先进入 `master`，再同步到 `release/snb-dev`。确认弹窗、为生产发布增加的差异预览组件和生产发布进度通知等当前界面扩展，仅进入 `release/snb-dev`。

全部任务 Tag 功能、Genbu 集成和生产发布工作流仅在 `release/snb-dev`。公共版不提供这些功能入口或执行逻辑。

QA 与产品版功能相同：保留任务创建、搜索、置顶、归档、恢复和删除，需求内容与评论，资料阅读和文本编辑，任务说明与共享 AGENTS/模板，Codex、AI 命名、Skills、插件、MCP 及全部实用工具（包括端口查询和结束进程）。资料 Git 同步、Git 扩展来源和必要的 Git 设置继续保留。

QA 与产品版移除研发任务详情、服务和代码仓库配置、代码克隆及工作区准备、Git Worktree/分支/提交/推送/合并/审阅/状态、任务 Tag、Genbu、生产发布及生产分支、IDE/Cursor 和研发设置。裁剪覆盖界面、后台、配置与旧路由；同步修复时不得恢复这些能力。

QA 和产品版与研发版独立安装，并各自使用独立的默认应用数据目录 `~/silverwing-qa`、`~/silverwing-product`，任务和资料默认放在各自目录的 `tasks`、`materials` 下。它们使用独立安装标识和快捷方式，并用 `edition: qa`、`edition: product` 区分配置及任务数据；旧研发配置和任务不能直接导入。两版分别查询本版更新渠道，QA/产品 GitHub Release 均设置 `make_latest=false`，不占用研发版的默认 latest 发布。

各版本按各自当前 schema 读写配置与任务清单；不支持跨版共用配置、导入对方版本的数据或保证跨版数据兼容。分支切换不会自动删除本机文件、Git 历史或工作区。

## 后续同步规则

- 公共修复和功能先进入 `master`，验证后再合并/同步到 `release/snb-dev`。
- 内部功能在 `release/snb-dev` 开发并仅回合该分支；不把整个内部分支反向合并到 `master`。
- 同步时吸收 `master` 的公共更新，并在 `release/snb-dev` 保留其内部实现。
- 对 QA、产品和研发版均适用的修复，按各自实现分别同步并验证；QA 与产品版保持功能一致和各自安装、数据及更新身份。不要把整个研发分支合并进裁剪版本。
- 同步 QA/产品版时检查导航、配置、后台 Action、数据格式、说明模板与安装包边界；原本只适用于研发能力的改动留在研发版。
- 维护分支、文档或代码同步完成不代表已经生成、发布安装包或 GitHub Release；二进制发布仍需各自独立的发布与验证流程。
