# 原生 Markdown Live Preview 与 MyGO 升级

## 目标

任务资料中的可写 Markdown 使用连续的原生编辑面：光标进入的内容显示必要语法，其余内容保持排版。表格、Mermaid 等复杂块编辑时原地显示该块源码。整篇共用文本缓冲区、光标、选区、组合输入和撤销历史。

第一期只开放任务资料。已有只读的任务说明、AGENTS、Skills、Git 差异等入口继续使用阅读器；原有任务本地笔记等显式源码编辑入口保持原行为。实现使用 Go/MyGO 原生输入、布局和绘制。

## 当前原生阅读如何工作

`ui/markdown.View` 将 Markdown 交给增量 parser，块和行内节点保留原文位置；随后构造原生 RichText、Column、Row、Image 和代码块。Windows 使用 DirectWrite 排版文字，再经 D3D11 绘制。正文展示没有经过 HTML；剪贴板导出的 HTML 属于独立功能。

阅读器已有显示文字到原文位置的映射和跨段选择。它的选择控制器是只读的，尚不能负责全文编辑、组合输入、跨块删除及撤销。此前按块或按单元格创建输入控件的编辑方式，也不能直接满足连续编辑要求。

## 编辑架构

- `editor.Buffer` 持有唯一文本和撤销事务；`markdown.EditorState` 持有全文光标、选区、组合输入及显示投影。
- 编辑面只绑定一个 `TextInputClient`。活跃的文本内容显示源码，非活跃内容使用原生 Markdown 排版；列表和引用保留共同的容器布局，显示块不拥有独立编辑状态。
- 编辑及解析位置统一使用 LF 逻辑文本的 UTF-8 字节偏移。显示字形和系统输入法的 UTF-16 位置经过映射；保存和原文复制使用同版本的保真快照。
- 组合输入期间保持活跃区域稳定，避免语法显隐打断输入或使候选位置漂移。组合输入提交后再进入文本事务及自动保存。
- 可写任务资料只有实时预览和源码两种模式。新打开文档默认实时预览，同一文档刷新保留当前模式；两种模式共享同一份文本。显示投影不重新序列化全文，保留未编辑内容、BOM、混合换行、注释、Frontmatter 和相对图片路径。
- 任务资料保存继续核对身份、根目录、文件类型和磁盘基线。保留 3 MiB 限额、650ms 自动保存、Ctrl+S、草稿恢复与冲突处理。

MyGO 的富文本 Markdown 解析/导出是内容转换：表格会变为 tab 分隔段落，代码围栏也会重新生成。它可以提供输入与排版参考，但不能作为原文保真的保存管线。[解析实现](https://github.com/egoist/mygo/blob/v0.7.3/ui/richtext/markdown_parse.go)、[导出实现](https://github.com/egoist/mygo/blob/v0.7.3/ui/richtext/markdown.go)

单一文本模型加显示投影的思路也可参考 [CodeMirror 的装饰机制](https://codemirror.net/examples/decoration/)；本项目不引入该 JavaScript 组件。

## 排版稳定性改动

可写资料现在默认实时预览，只保留源码切换。列表使用原文标号和实际空行，焦点切换不再套用阅读器的连续编号、额外项间距；空项和复杂内容前的标号仍可定位和编辑。引用内标题保留样式，标题源码态保留颜色和分隔线，文末换行只有一个显示归属。

图片资源按文档、链接和信任范围缓存，移动前文、临时显示图片源码和重复引用不会反复丢弃已加载图片；删除最后一个引用才释放。图片后的文字映射统一使用显示文本偏移。Mermaid 右上角的放大和更多按钮单独处理点击，图表标题和正文仍可进入整块源码编辑。

编辑器在图表或图片异步改变尺寸时保持可见源码位置，并区分布局引起的滚动范围收缩、用户主动滚动和正在更新的组合输入。稳定的输入法候选也参与此保持机制。虚拟全文按源文和组合输入状态复用，避免为每个列表前缀复制全文。

本轮证据保存在 `build/markdown-live-stability-20261030/`，包含固定基线、累计差异、修复前后测试和独立审查记录。旧截图与旧便携包属于前期证据。
