# 首次配置

本文适用于 Silverwing 0.0.1（当前 Go/MyGO 版），内容已按当前代码核对，核对日期为 2026-10-19。首次打开时可以先配置任务目录、Git 和本机仓库；只有要从 Meegle 需求创建任务时，才需要继续完成 [Meegle 接入](04-Meegle接入.md)。

> [!tip] 建议先用示例仓库走通流程
> 下文的路径和仓库名都是虚构示例。请换成自己电脑上的真实 Git 仓库；不要把示例目录直接当成必须创建的目录。

## 先认识三层配置

Silverwing 用**项目组**归类相关服务；每个**服务**绑定一个本地 Git 仓库；服务中的**工作区模块**决定创建任务时要从这个仓库准备哪些独立工作区，以及使用 Worktree 还是独立克隆。添加仓库时，程序会自动生成同名服务和一个 `default` 模块，之后可以按项目实际结构调整。

## 必需配置

### 1. 确认任务根目录

打开左侧「设置」→「存储」→「目录」，检查「任务根目录」。Silverwing 首次初始化会创建默认任务目录；默认位置可用时可以直接保留。任务根目录保存 Silverwing 创建的任务清单、任务级说明和 Git 工作区，不是源代码仓库目录。业务资料可以放在后文所述的独立资料根目录中。示例：`D:\dev\silverwing-tasks`。

需要更换时，点「浏览」选择目标文件夹。已有任务时，Silverwing 会先读取迁移预览，再让你选择迁移旧任务或直接切换目录；迁移前请关闭相关工作区的 IDE 和终端。切换会检查目标目录是否可写。保存成功后重新打开「目录」页确认显示的是新路径；如果提示不可写，改选当前账号有权限的位置。

### 2. 检查 Git

打开「设置」→「Git」→「Git 配置」。保留「Git 可执行文件路径」为空时，应用会尝试从系统 PATH 自动检测；若没有检测到，选择本机 Git 可执行文件，修改后自动保存。然后用卡片右上角菜单中的「刷新 Git 状态」重新检查。

成功时，「命令状态」显示可用，并能看到 Git 版本及全局用户名、邮箱。用户名和邮箱应符合团队提交要求；若没有显示或内容不对，请先在团队认可的 Git 安装和身份配置中修正，再刷新。Silverwing 只检查 Git，不负责安装 Git，也不会替你配置远程仓库凭据。

### 3. 建立项目组并登记仓库

进入左侧「服务」。在仓库与项目组操作菜单中选择「新建组」，填写「项目组名称」并保存。选中这个组，点击「添加仓库」→「选择目录…」，选择一个或多个**本地 Git 仓库根目录**，再确认添加。应用会检查每个目录是否为可用 Git 仓库；无效目录和重复仓库会跳过并说明原因，已有配置不会被覆盖。

例如，把 `D:\dev\repos\order-service` 和 `D:\dev\repos\payment-service` 加入「订单域」组。成功后列表会显示仓库名称、本机路径和模块数量。初始服务主分支会参考 Git 检测到的默认远程分支；如果没有检测结果，默认值可能为 `origin/master`，因此每个仓库都要实际核对。

点击仓库行的「配置」进入「服务配置」→「Git」，检查「主分支」是否为真实存在的 `remote/branch`，例如 `origin/main`。界面可读取仓库远程和分支候选；若远程信息未更新，打开更多操作并点「刷新本地 Git 信息」。然后进入「工作区模块」，确认 `default` 模块名称和 Worktree 策略；一个仓库拆成多个可独立工作的组件时，可添加多个模块。点对话框底部「保存配置」后，修改才会生效，且只影响之后创建的任务。

## 选配配置

- **IDE**：在「设置」→「开发工具」选择常用 IDE。路径留空时会自动检测；也可手动选择程序路径，再从更多操作中点「测试打开」。单个服务也能在「服务配置」→「开发工具」设默认工具。若没有配置，仍可先使用 Silverwing 的仓库与任务管理。
- **Codex CLI**：如果要用 Codex CLI 做需求命名或 Codex 扩展管理，检查「设置」→「任务」→「任务创建区」中的 Codex CLI 状态和路径。外部 CLI 需要你按团队方式安装；路径留空时 Silverwing 会自动检测。仅打开 IDE 工作区不要求启用 AI 命名。
- **分支规则**：在「设置」→「Git」→「分支名设置」配置默认前缀，例如 `feature/{num}_{ai}`。`{num}` 表示需求编号，`{ai}` 表示 AI 英文描述；留空即可不设置全局前缀。
- **说明文件**：在「设置」→「AGENTS.md」→「全局与组说明」补充团队规则；「任务说明模板」用于复用任务级说明。它们是可选上下文，不代替项目自身的构建或测试说明。
- **任务资料目录**：在「设置」→「存储」→「目录」分别配置资料根目录和相对的子目录后才会启用；不做资料归档或同步时可以留空。

## 完成核对

创建第一个任务前，确认「设置」中任务根目录可用、Git 状态可用；「服务」中至少有一个项目组，组内仓库路径正确，服务启用且至少有一个工作区模块。创建需求任务还需要 [完成 Meegle 接入](04-Meegle接入.md)。若要从需求页创建，检查「需求」页面出现 Sprint 和需求条目；创建表单打开后仍需核对服务、模块和分支，再点击「检查并创建任务」。
