# 配置持久化与恢复机制

[返回知识库目录](../Index.md) · [相关：配置项参考](../配置与数据/19-配置项参考.md) · [相关：目录与数据存储](../配置与数据/20-目录与数据存储.md) · [相关：备份恢复与迁移](../配置与数据/21-备份恢复与迁移.md)

Silverwing 将应用配置保存在应用 Home 的 `config` 子目录。公共版管理七个 JSON 分片并解码为 `AppConfig`，按当前 schema 校验配置；任务目录、任务资料、Codex MCP 配置与本机偏好各自有独立存储，不因配置备份自动包含。见[配置项参考](../配置与数据/19-配置项参考.md)。

## 公共版管理的分片

| 文件 | 内容 |
| --- | --- |
| `layout.json` | 项目组 ID、名称和显示顺序。 |
| `workspace.json` | 任务根目录、默认分支名前缀、仓库目录和 Git 元数据。 |
| `services.json` | 按组 ID 保存的服务、模块、复制规则和初始化命令。 |
| `tools.json` | 终端覆盖、IDE 路径、默认 IDE、任务创建后自动打开的工具。 |
| `git.json` | Git 写保护分支与 Git 可执行文件路径。 |
| `integrations.json` | AI 命名、Meegle、Codex、代理、Lark、任务资料目标、Marketplace 与 Skill 来源。 |
| `appearance.json` | 主题、工具导航可见性、任务和工作区工具栏与复制图标设置。 |

配置目录只接受当前 schema 定义的分片和字段；缺少必需分片、包含未知文件或字段、类型或关系无效时，读取会报错。组的显示数据与服务配置分别在 `layout.json` 和 `services.json`；解码会按组 ID 合并，并拒绝重复 ID、缺失组或两侧 ID 集合不一致。修改全局配置时，存储比较新旧分片，只写变化的文件。

## 写入、锁与一致读取

每次修改先取得按配置目录区分的进程内互斥门，再申请 `locks/config.lock` 的操作系统排他锁。Windows 使用 `LockFileEx`，其他平台使用 `flock`；操作系统在进程异常退出时释放锁。锁文件可以继续留在目录中，文件存在不代表锁仍被占用。跨进程锁是立即失败式：其他 Silverwing 实例正持有锁时会返回资源占用错误，应稍后重试，不要删除锁文件。

写入器先读取将变更分片的旧字节，再在配置目录写入临时文件、执行 `Sync`，之后逐个原子替换目标文件。单文件替换在 Windows 调用带替换和写穿标志的 `MoveFileExW`，其他平台使用同目录 `Rename`。若后续分片替换失败，存储尝试按反向顺序恢复本次已替换文件；恢复也失败时，会把替换错误和回滚错误一并返回。

这不是跨多个文件系统调用的普遍事务保证：非 Silverwing 程序若绕过锁读取，可能在连续替换期间看到新旧分片混合；进程或磁盘故障也可能使回滚无法完成。Silverwing 自己的配置读取走同一锁门，并在写锁释放后读取，从而避免正常并发读到半次提交。首次空 Home 的只读预览不会创建锁或初始化配置。设置页“日志”显示应用操作错误，不是逐分片写前日志或恢复日志。

## 严格读取与版本边界

当前运行时 AppConfig schema 为 `6.0.0`，公共版管理的分片文件保存整数 `schema: 6`，两者独立于产品版本。`schemaVersion` 由当前默认配置在解码时提供，并不作为顶层键写入分片。解码对已知字段执行结构、字段类型、枚举及关系校验；未知字段会被拒绝。组、服务和模块按稳定 ID 对应，不按数组位置配对。`.silverwing-shard-*.json.tmp` 暂存文件会在读取时忽略。

不支持的 schema 会明确报错，应用不会自动把未知版本读成默认值并覆盖。若文件缺失、权限错误或格式损坏，普通保存不能绕过验证；先保留现有目录和错误信息，再使用有效导出配置或备份走预览、确认和恢复流程。

## 备份、导入与恢复

已有配置发生实际变化前，存储会把当前七个 schema 分片打包到 `backups/silverwing-config-*.zip`。导出 ZIP 同样包含当前 schema 所需的配置分片。自动备份最多保留最近 10 个；超过数量时清理更旧备份。空配置首次初始化和无变化的保存不创建变更前备份。

导入在「设置 → 存储 → 配置与备份」选择 ZIP 后，先严格读取并校验，显示变更字段、路径变化以及当前电脑上不存在的 IDE 路径；路径检查只判断是否存在，不验证 IDE 能否启动。当前 schema 可识别、分片可读但 JSON 内容或关系校验失败时会给出替换提示。确认后导入器会再次读取 ZIP、在锁内读取当前分片、创建当前配置备份，最后替换变化的分片。预览计算 ZIP 指纹，但当前界面的确认动作只传递来源路径，没有把预览指纹传回导入器校验；若预览后该 ZIP 被替换，实际导入内容可能与预览不同。预览不会改当前配置或创建备份。恢复列表当前提供确认对话框后直接恢复；后端有严格预览接口，但列表按钮未调用该预览流程。确认恢复会先备份当前配置，再用备份替换。

恢复只处理应用配置分片，不迁移或删除任务根目录中的任务、Git 工作区、外部资料目录、CLI 登录状态或 IDE 安装。若导入后路径指向另一台电脑的目录，需要在设置中重新选择可用路径。配置与备份页支持读取备份、恢复及删除所选备份。

当前分片齐全、schema 可识别但配置内容损坏时，确认导入会先把读取到的旧分片归档，再替换。分片 schema 不受支持、权限或锁错误会在预览阶段直接报错；缺片、目录含未知文件等结构问题可能被预览显示为损坏警告，但确认写入时无法读取完整当前快照，也就无法创建变更前备份，替换会失败。此时不要清理现场；保留配置目录与应用日志，用有效的外部导出 ZIP 重试，并查看返回的具体读写或锁错误。不要手动拼出缺片来让界面“看起来正常”。

## 多实例边界

相同配置目录的 Silverwing 实例共享操作系统锁；同一进程内的 ConfigStore 也按清理后的绝对目录路径互斥。锁保护的是 Silverwing 通过 ConfigStore 执行的配置读写，不会协调编辑器、同步程序或手工脚本。不要让多个程序直接改写分片；若另一实例报告“资源被锁定”，先确认该实例的读写操作结束，再重试。
