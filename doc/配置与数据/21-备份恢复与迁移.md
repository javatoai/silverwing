# 备份恢复与迁移

[返回知识库目录](../Index.md) · [上一篇：目录与数据存储](20-目录与数据存储.md) · [下一篇：网络代理与 CLI 环境](22-网络代理与CLI环境.md)

本文适用于 Silverwing **0.0.1 Go / MyGO 版**，核对日期为 2026-10-19。操作前先确认当前应用 Home、任务根和资料根；「配置备份」只保存设置，不等于任务、代码仓库和资料的完整备份。

![应用 Home、任务根与资料根的存储边界示意图](../assets/config-data-map.png)

## 导出、预览导入与恢复配置

配置导出包只包含当前配置的 8 个分片，不包含任务目录、工作区代码、外部任务资料、桌面偏好、草稿缓存、日志、外部 Codex 配置或 Silverwing 管理的 Codex 缓存。配置里有绝对路径，因此另一台电脑导入后，Git 仓库、IDE、CLI、任务根和资料根仍需按新电脑的实际路径核对。

### 导出当前配置

1. 打开「设置 → 存储 → 配置与备份」，点击「导出配置」。
2. 导出完成后，Silverwing 会在文件管理器中显示生成的 ZIP。默认保存到当前 Home 的 `backups/`，文件名以 `silverwing-config-` 开头。
3. 将需要长期保留或带到另一台电脑的 ZIP 复制到独立的安全位置。配置变化时自动创建的回滚备份最多保留 10 个，较旧的同名 ZIP 可能被清理。

### 导入配置

1. 在同一页点击「导入配置」，选中 Silverwing 配置 ZIP。
2. 先看预览里的变化项和失效的开发工具路径。预览只检查 ZIP 结构与配置，并提示找不到的开发工具；不会替你确认仓库、任务根或资料根在新电脑上是否正确。
3. 若来源、配置内容和路径都符合预期，点击「确认导入」。导入会用 ZIP 中的配置替换当前配置；改写前按当前配置备份机制保留现有分片。任务目录本身不会因此删除或搬动。
4. 导入后打开「设置 → 存储 → 目录」和「设置 → Git / 开发工具 / CLI」，确认每个路径和命令指向本机可用位置。重新打开任务列表，检查任务数和工作区状态。

从选择文件到确认导入期间，保持 ZIP 内容不变；若更换或修改了该文件，请取消并重新选择、预览。当前确认操作会按所选路径重新读取 ZIP，不会锁定预览时的文件内容。

预览报错、来源不是当前选中的 ZIP，或变化项无法解释时，关闭窗口并取消；确认前不会导入。已有配置 ZIP 可在「配置与备份」列表查看，点对应的「恢复」并确认，使用该 ZIP 替换配置。恢复配置不会删除任务目录。若 ZIP 已损坏或 schema 不兼容，恢复会失败并保留现状。

列表中的备份可勾选后点「删除所选」，确认后永久删除所选 ZIP 文件。删除备份不会删除配置、任务或代码。默认 Home 的备份目录见页面显示的完整路径。

## 更换任务根目录

进入「设置 → 存储 → 目录」，在「任务根目录」选择新目录。失焦或选择目录后会出现三种选择：**迁移旧任务数据**、**直接切换**或**取消**。

- **迁移旧任务数据**：先看迁移预览中的任务数、工作区数、预计大小和阻塞原因。目标目录需要可写；有任务时必须为空。预览可执行后再确认，迁移过程会复制或移动任务目录、检查清单和 Git 工作区、更新清单中的路径，最后更新配置。跨磁盘会复制并校验；迁移期间关闭这些工作区的 IDE 和终端。若预览提示工作区、清单或资料路径问题，先处理原因再重新预览。
- **直接切换**：只把配置指向新目录，并保留旧目录内容。它不搬迁任务或工作区；目标目录中已经存在的 Silverwing 任务可能会在刷新后显示。适合准备空白任务空间或手动复制完成后的切换，不能把它当作迁移完成。
- **取消**：不更改已保存的任务根目录。

任务根迁移只转移实际位于某个任务目录内、并被迁移映射覆盖的路径。若任务资料在独立的外部资料根，文件继续留在原处；迁移预览会列出每个任务资料写入路径迁移前后的值。直接切换不会移动任何资料。迁移完成后检查新根中的任务清单、工作区 Git 状态和任务资料路径；若程序报告旧目录待清理或恢复状态未完成，先按提示处理，不要手工删除迁移标记或恢复日志。

## 更换任务资料根

在同一「目录」页修改「任务资料根目录」和相对的「任务资料子目录」。保存会创建新根目录，但不会单独测试写权限；后续准备任务资料时仍可能因权限不足失败。此操作不会复制旧资料，也不会重写既有任务清单里的 `WriteRoot`。因此，新任务使用新根，旧任务仍从清单记下的原路径读取。迁移前先用文件管理器复制需要保留的资料，更新后分别打开新旧任务的资料页检查文件和链接。

## 换电脑的完整迁移

下面以虚构的 `REQ-1001` 任务为例。若新电脑能保持所有旧目录的**完整绝对路径**，并同时带上源仓库、任务根和外部资料根，现有 Worktree 路径更容易继续有效。换盘符、换操作系统或更改仓库位置时，导入配置不会改写任务清单中每个工作区的路径；不能假设任务 ZIP 或配置 ZIP 会自动修好这些路径。

1. **旧电脑**：在「配置与备份」导出配置 ZIP；分别备份当前任务根、独立资料根和源 Git 仓库。需要保留全局/组说明和任务说明模板时，单独备份应用 Home 的 `agents/`；需要保留 Silverwing 管理的 Codex/Skill 状态时，按需备份 Home 的 `codex/`。这两个目录不在配置 ZIP 中，备份时也要按敏感资料保护。按团队的代码保留流程检查未提交更改和未推送提交，并确保备份介质可读。若资料根位于任务目录之外，必须单独备份。
2. **新电脑**：安装 Silverwing，先确认新应用 Home，再按安全要求转移上述目录副本。将需要保留的 `agents/`、`codex/` 放回对应 Home 子目录；外部工具的登录与授权状态仍需按各工具要求重新核验。保留原路径布局时，先恢复源仓库，再恢复任务根和资料根；检查 IDE、Git、Meegle/Genbu CLI 路径。
3. 在新 Silverwing 的「配置与备份」导入 ZIP，查看预览并确认；随后在「目录」页把任务根和资料根指向新电脑的实际位置，并重新核对子目录。资料根切换只保存设置，不代替资料副本恢复。
4. 打开任务列表核对 `REQ-1001` 等任务、归档状态、任务说明和 Tag 历史；逐个检查工作区 Git 健康状态与资料文件。卡片出现「修复工作区」时，先打开修复预览，看清目标分支、备份或重建步骤，再决定是否确认。
5. 若工作区仍引用旧电脑路径，或修复预览不能安全执行，不要删除旧备份或原电脑数据。保存好代码改动和资料后，在新电脑按正常流程重建工作区或任务，并从备份还原需要的任务说明与资料；验证完成前保留原电脑副本。

只有在新电脑确认任务、工作区和资料都可读、Git 状态符合预期后，才把迁移视为完成。应用 Home 下的桌面偏好和草稿缓存不在配置导出 ZIP 中；确实需要迁移时，需另行处理相应 Home 文件，并按各自数据范围核对，不能把它们与任务数据混为一份备份。
