# 日常使用指南

silverwing 用于把一个研发任务准备成明确、可追溯的本地 Agent 工作区。它管理任务、服务工作区、Git 风险状态、`AGENTS.md` 和当前唯一的交付动作：Tag。

## 适用场景

- 一个需求需要同时修改多个服务；
- 研发使用 IDEA、WebStorm、Codex 或 Cursor 在本地开发；
- 需求来自飞书，团队按组（业务线）管理服务；
- 提交测试环境前需要创建可追溯的 Tag。

silverwing 隔离的是代码工作目录和 Git 工作区；端口、数据库、Docker、凭据和外部测试环境仍由项目本身管理。

## 首次设置

1. 首次启动会自动创建 `~/silverwing/tasks` 并将它设为任务根目录，不需要手动选择。每个任务会在该目录下创建一个子目录；如需调整，可在设置页选择新目录。
2. 使用“添加仓库”选择本地 Git 主仓库。可多选目录；非 Git、Bare 仓库、临时 Linked Worktree 和重复仓库会被跳过。
3. 在组中添加服务并设置显示名称、主分支、工作区策略及需要时的 Tag 规则。模块默认继承服务主分支和测试 Tag 目标，也可分别自定义。
4. 可选：填写 IDE、终端和任务完成后默认打开的工作区工具。
5. 可选：在“Meegle”中选择项目。创建任务时会查询已配置空间中属于当前登录用户的进行中 Sprint 需求。

未创建额外组时，应用保留一个默认组，并在任务与服务页面隐藏组层级。

设置按分类展示：任务下的“任务创建区”可分别选择创建后自动打开 Codex、Cursor，并配置 AI 生成分支名和文件夹名；研发配置保留“项目组”和“开发工具”；Git 分类通过顶部“Git 配置｜分支名设置｜Tag 设置”切换，默认显示 Git 配置，“分支名设置”保留全局默认前缀；Codex 分类管理插件，Skill 安装分类管理 Git 来源与安装。“任务协作说明”管理全局与组级 `AGENTS.md`，任务说明模板仍用于创建任务时填充人工说明。

“Codex 插件”仅管理带 Marketplace 清单的 Git 来源。添加来源会注册到本机 Codex 并读取可用插件；之后只有手动刷新才会联网更新。插件安装或卸载后需要新建或重启 Codex 会话。“Skills”管理外部 Git Skill 来源：默认扫描仓库中的 `.agents/skills` 与 `skills`，安装到 `~/.agents/skills/<name>`。若已有同名 Skill，必须明确确认接管，覆盖或卸载前会在 `~/silverwing/codex/skill-backups/` 留下本机备份。

如果当前任务根目录已有任务，更换目录后会先显示迁移确认。迁移期间请关闭相关 IDE 和终端；silverwing 会保留脏文件和未跟踪文件、修复标准 Worktree 注册，并在全部校验成功后切换配置。失败会自动恢复旧目录；若只剩旧目录因文件占用无法删除，迁移仍然生效并显示待清理路径。

## 创建研发任务

1. 点击“创建研发任务”。
2. 可选地手工填写需求编号或飞书需求链接，或从候选需求中选择。输入需求时，任务资料目录使用下一步填写的文件夹名称；不会替换该名称。设置中的任务资料根目录和资料子目录均已配置时，创建页会只读预检并显示预计新建或复用的完整资料路径；任一项未配置时，创建流程不会展示或尝试创建任务资料目录。任务资料目录按 Sprint 分组：本地已有可复用目录时始终复用；否则需求只关联一个 Sprint 时直接使用它（无论是否进行中），关联多个时使用唯一进行中的 Sprint。
3. 填写“任务名称 / 文件夹名称”。它会原样成为任务目录名，不能包含 Windows 非法字符、保留设备名、末尾点或空白。
4. 确认任务分支。组的默认前缀可包含 `{num}`；它会从需求编号、需求链接或普通文本中的最后一段数字解析。
5. 选择本任务需要修改的服务。服务搜索只过滤展示，不会清除已选服务。
6. 在右侧填写任务人工说明，或预览最终 `AGENTS.md`。选择工作区工具后点击创建。

创建期间可以继续查看任务和复制信息；只有会与当前 Git 或配置写入冲突的动作会被禁用。

## 服务与工作区策略

### 标准 Worktree

适用于需要为任务创建独立 Feature 分支的服务。创建时会从最新已获取的主分支远程引用创建 Worktree，不会切换或移动主 checkout。每个模块始终获得独立物理 Worktree；单模块沿用任务分支，多模块默认使用“任务分支-模块名”，创建时可分别搜索或手工覆盖本次主分支和目标分支。

### 独立克隆

适用于需要直接在固定远程分支工作的服务。它从 `origin` 完整克隆并检出选定分支，不额外创建 Feature 分支、Worktree 或执行 Bootstrap。多个任务同时使用同一远程分支时仍可能产生业务层面的代码冲突，团队需要自行协调。

## 任务详情与 Git 状态

需求列表、需求正文和标题／状态信息会按 Meegle 登录身份、项目及查询条件缓存到 `~/silverwing/cache/requirements`，从最后一次成功读取起保留 14 天，重启后仍可复用。读取命中不会延长有效期，缓存访问时会自动清理过期记录。点击对应刷新按钮会重新读取最新数据，成功后覆盖缓存；失败会显示错误并保留尚有效的旧缓存。读取缓存前仍会核对当前登录身份。

每个工作区显示：

- `无未提交` 或 `N 个文件未提交`：包含 staged、unstaged、冲突和未跟踪文件，不包含 ignored 文件；
- `已推送` 或 `N 个提交未推送`：只比较本地已知 upstream，不执行 fetch；
- `检查中`：正在读取本地 Git 状态，不会 fetch 或切换分支；
- `工作区不存在`、`不是有效的 Git 工作区`、`Git 仓库身份不匹配`、`分支不一致`、`Detached HEAD` 或 `存在进行中的 Git 操作`：对应行会展示完整原因和修复图标。

点击修复图标会先展示预计动作。失效的普通 Worktree 或独立克隆目录会先改名保留为同级备份；仅远程存在任务分支时必须明确确认复用。

任务详情可逐个复制当前实际分支和路径、打开 IDE/终端/文件夹、添加服务，以及在满足开关条件时构建 Tag。创建任务时，分支输入框可搜索所选标准 Worktree 服务的远程 Heads；下拉查询不会执行 fetch 或读取 Tag。

服务模块的 Git 操作区提供“合并远程主分支”，悬停可查看合并方向。它会拉取该模块记录的远程主分支并合并到当前任务分支；工作区有未提交修改或进行中的 Git 操作时会拒绝执行。发生冲突会保留当前工作区的冲突现场，并显示冲突文件及可复制的说明；处理后需要完成或自行中止合并。此操作不会自动推送。

启动后，silverwing 会在后台静默查找尚未填写路径的开发工具。Windows 只检查 Program Files、`%LOCALAPPDATA%\Programs`、JetBrains Toolbox 已知目录和 PATH；macOS 只检查 `/Applications`、`~/Applications`、JetBrains Toolbox 已知目录和 PATH，不会联网或递归扫描磁盘。手动保存的路径优先级最高，即使当前无效也不会被自动结果覆盖；未找到时不会提示。

开发工具设置会显示每项路径是否可用，并把“手动选择”“测试打开”及“恢复自动/重新检测”放在路径输入框右侧。Git、Meegle 与 Genbu 命令同样显示当前命令来源；清除手动路径或点击“恢复自动”后，会重新使用自动探测或 PATH 回退。

终端默认无需填写路径。Windows 自动选择 Windows Terminal，找不到时使用 Windows PowerShell；macOS 使用系统 Terminal，Linux 使用 `x-terminal-emulator`。设置页会显示当前实际选择，手动路径始终优先，并可随时恢复自动模式。

开发工具中的“临时选择开发工具”默认关闭。关闭时，每个服务都直接使用其默认工具打开；开启后才显示临时选择菜单。任务创建完成不会因为这个开关自动打开服务。

任务资料支持 Markdown、JSON、CSV、TXT 和 PDF 预览，也支持 Python、Shell、PowerShell、批处理、Java、Kotlin、JavaScript、TypeScript、SQL、YAML、HTML、CSS 和 Properties 等文本代码的语法高亮。代码预览保留原始缩进和换行，可选择复制、查找及横向滚动；切换源码可查看未经着色的原文。其他文件仍可通过系统默认应用打开。

任务资料页单击文件使用临时预览，双击或点击固定标签按钮可保留多个文档；关闭标签可用 Ctrl+W。Ctrl+P 按文件名快速打开，Ctrl+F 查找当前文档，Ctrl+Shift+F 搜索整个任务资料目录（文本及 PDF），结果可直接定位到文本行或 PDF 页。Markdown 工具栏的“文档目录”可跳转标题。外部软件修改资料后，当前预览会在检测到目录变化或窗口重新激活时更新，并保留阅读位置；正在编辑的 Markdown 会进入下面的冲突处理流程。

文档列表顶部的排序按钮可切换“按名称”和“最近修改”。文件夹始终在前，每层目录独立排序；最近修改按时间从新到旧排列，时间相同按名称排列。切换排序会保留当前打开的文档，每个任务分别记住排序选择，重启后恢复。

### Markdown 编辑与恢复

选中 Markdown 后，点击文件标题右侧的“编辑 Markdown”进入编辑器；“查看任务资料预览”返回渲染预览。编辑器使用等宽文本区，底部显示“有未保存修改”或“已保存”以及当前大小。点击“保存”图标或按 Ctrl+S 才会写回资料文件；切换任务资料页、切换标签或关闭窗口前输入会自动保存为本机草稿，草稿在重新打开 silverwing 后也会尝试恢复，未点击保存前不会改动原文件。点击“撤销修改”后还需在确认框中点击“确认撤销”，才会恢复最近一次已保存内容并清除该文件草稿；不确认则保留编辑内容。编辑器单个 Markdown 文件支持到 512 KB，超过后应使用外部编辑器。

如果外部软件在编辑期间改动了同一个文件，编辑器会提示“文件已被外部修改，当前草稿尚未覆盖外部内容”。“查看外部内容”会打开可独立滚动的外部文件窗口；“使用外部内容”会先打开确认框，点击“确认替换”后才放弃本地草稿并载入磁盘版本；确认仍以当前内容为准时选择“保留草稿并覆盖”。保存失败会在编辑器内显示原因，处理文件占用或路径问题后可再次点击保存；如果草稿缓存失败，点击“重试缓存”重新写入本机草稿。

### 图片预览

任务资料内的 PNG、JPG/JPEG、WebP、GIF、BMP 和 ICO 可直接预览；GIF 只显示第一帧。预览工具栏提供“上一张图片”“下一张图片”和“放大查看图片”，计数旁显示当前图片尺寸。资料面板内嵌预览和“放大查看图片”层都支持减号、加号、滚轮或键盘 +/- 缩放，以及鼠标拖动或方向键平移；“适配”或按 0 恢复适配窗口，按 1 查看原始尺寸，放大查看层按 Esc 关闭。图片读取失败时点击“重试图片”；仍无法解码或超过预览限制时，使用文件标题右侧的默认应用或“用其他应用打开…”。

任务资料文档列表右键支持重命名、新建 Markdown 和文件夹。更多资料操作中可导入文件、粘贴截图；文件也可直接拖入任务资料页。文档列表获得焦点时，Ctrl+V 将剪贴板截图保存到当前任务资料目录。同名文件需要选择另存、取消或支持时替换。任务更多菜单和任务资料更多操作中的“复制 AI 上下文”会汇总需求、服务分支与选中资料，先预览并删改，再复制到剪贴板。

Git 设置页只读取本机 Git 可执行文件、版本、用户配置来源、凭据助手名称、已配置仓库的当前分支、HEAD、upstream、ahead/behind、状态、Worktree 和原始远程 URL，不执行任何联网 Git 命令。

## AGENTS.md

说明分为三层：

```text
~/silverwing/agents/global/AGENTS.md
~/silverwing/agents/groups/<groupId>/AGENTS.md
<任务目录>/AGENTS.md
```

设置页可直接编辑全局或组说明，也可以在对应文件路径用外部编辑器修改。任务级文件保留人工说明区；保存任务说明时，系统区会按最新任务、全局说明和组说明重新生成。外部编辑与未保存本地编辑冲突时，必须选择磁盘版本或本地版本。

## Tag 与归档

Tag 只在组开关和服务模块/独立克隆子开关都开启时可用。构建前会执行 Git 风险检查和临时合并预检；不会 Force Push、自动 Rebase 或自动解决冲突。详细规则见 [安全与 Tag 流程](SAFETY-AND-TAG-FLOW.md)。

在“设置 → Git → Tag 设置”中开启“允许在任务详情修改测试目标分支”后，采用合并模式的服务模块可通过任务详情中的“更多 → 设置测试目标分支…”修改远程和测试目标分支。此开关默认关闭，关闭时隐藏该入口和对应的“更多”按钮。保存后，当前任务该模块的新 Tag 使用新目标，其他任务与服务默认配置保持原值。历史记录的重试、部分推送恢复和重新打 Tag 继续使用历史记录的原目标；原目标失效时会报错，不会自动换成新目标。

归档或删除前会检查未提交内容、未推送提交和进行中的 Git 操作。强制归档可能丢弃未保存文件，只应在确认风险后使用。
