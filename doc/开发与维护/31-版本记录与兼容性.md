## 当前兼容性快照

下表是按当前源码核对的版本快照，不等于历史发布清单。产品展示版本、持久化数据格式、Agent 上下文协议以及构建工具依赖各自服务于不同边界，升级时要逐项判断，不能仅凭产品版本号推断旧数据一定可读。

| 项目 | 当前值 | 用途与兼容边界 |
| --- | --- | --- |
| Silverwing 产品版本 | `0.0.1` | UI 与发行包使用；发布标签须匹配 `v0.0.1`。 |
| 应用配置 schema | `6.0.0`（配置分片版本 6） | 配置存储只接受当前 schema；不支持时会报错，不静默重写旧配置。 |
| 任务清单 schema | `2.0.0` | `silverwing.json` 使用的格式版本；读取与写入都按当前版本校验。 |
| Agent 任务上下文协议 | `2` | `protocolVersion` 约束任务 Agent 文档；不等同于产品版本或 Codex RPC 版本。 |
| Agent 文档布局 | `REFERENCED_V2` | 说明任务上下文的文件组织方式，是布局选择，不是上述协议号。 |
| Go 工具链 | `1.27.1` | `go.mod` 和 CI 读取的构建工具链版本。 |
| MyGO | `v0.5.0` | 固定上游版本，由本仓库 `third_party/mygo` 中的补丁副本替换。 |
| Mermaid 渲染器 | `mmdr v0.3.1` | 构建时按平台打包的离线原生程序。 |
| PDFium | `157.0.8086.0` | 构建时按平台打包的 PDF 原生运行库。 |

代码把 Codex app-server 握手中的 `clientInfo.version` 固定为 `2.1.8`。这是 Silverwing 对外报告的客户端身份值，不会替代 Agent `protocolVersion: 2`，也不能据此推断本机 Codex CLI 实际安装版本。

## 升级时看三层数据

升级前先关闭应用，并备份应用 Home、完整任务根目录和单独的资料根目录。配置备份只保护配置数据，不包含任务清单、Git 工作区或外部资料；不能把一个配置 ZIP 当作完整回滚点。步骤见[备份、恢复与迁移](../配置与数据/21-备份恢复与迁移.md)。

新产品版本是否能沿用旧数据，取决于配置 schema、任务 manifest 和 Agent 协议是否受支持。当前配置读取会拒绝不匹配 schema 的分片；任务清单读取也会拒绝不匹配版本。Agent 上下文协议不是应用配置版本；若任务协议校验失败，源码错误提示要求重建任务。不要直接手改 JSON 的版本字段来绕过校验，这可能让旧数据被当成新结构解释。

回退旧二进制前，先确认它支持现有配置 schema、任务 manifest 和任务上下文协议。若升级过程中已切换数据格式，稳妥回退需要恢复升级前配套备份中的应用配置、任务目录和资料，而不是只替换程序文件。保留 Git 仓库本身的提交与分支，并检查工作区是否有未提交改动；不要因 Silverwing 版本回退而删除用户代码。

更新 MyGO、mmdr 或 PDFium 属于依赖升级，即使 Silverwing 产品版本不变，也要核对补丁兼容性、资源架构、归档校验和许可证，并分别检查 Windows x64 与 macOS arm64 包。MyGO 补丁维护入口为 `third_party/MYGO-PATCHES.md`；发行资源基线见 `../../docs/RELEASE.md`。

## 版本记录如何维护

本篇记录源码产品版本 `0.0.1` 及独立 schema / 协议号的兼容性基线。新增发行记录时，以实际存在的标签、成功 workflow 和远端 Release 资产为依据，并记录平台、包类型及数据兼容说明。只有本地构建目录或普通 CI artifact 时，记录为构建产物，不作为正式发行版本。

## 源码入口

- 产品、配置、任务 schema 与 Agent 协议：`internal/domain/models.go`
- 配置版本严格读取：`internal/storage/config_store.go`
- 任务清单版本严格读取：`internal/storage/manifest_store.go`
- Agent 协议校验与默认值：`internal/domain/validation.go`、`internal/domain/unmarshal.go`
- 构建元数据与依赖锁定：`internal/buildinfo/buildinfo.go`、`go.mod`、`third_party/MYGO-PATCHES.md`
- 平台资源固定版本与发布条件：`../../docs/RELEASE.md`、`.github/workflows/native-build.yml`
