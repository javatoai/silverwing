# 任务资料 Git 同步

在 **设置 → 存储 → 目录 → 任务资料目录设置** 中配置资料根目录、资料子目录和 Git 仓库地址，然后从下拉框选择已有远程分支。分支列表支持刷新；空仓库需要先在远程创建分支。认证使用系统 Git 凭据和 SSH 配置。

自动同步默认关闭，周期默认 5 分钟，可填写正整数分钟。启用后仅在 SW 运行时执行，也可点击“立即同步”；编辑或保存仓库地址、刷新分支列表不会发起同步。修改仓库或分支后自动同步暂停，核对目标后使用“重新检查并恢复”。

资料采用“资料根目录／年份／需求编号-需求文件夹名／资料子目录”的结构，不增加 Sprint 或个人目录。创建任务时跨年份按完整编号查找，唯一匹配则沿用实际目录；重复、身份不符或读取失败时停止。旧平铺目录保留，不搜索、迁移或自动上传。

自动提交范围仅为年度需求下用户配置的资料子目录，包含全部正常文件、附件及增删改，并遵守 `.gitignore`；不跨越符号链接或嵌套仓库。同级 `temp` 固定为本地临时目录，不提交、不推送，也不接受 Git 覆盖。同事的其他目录和文件正常拉取，在 SW 中只读，可搜索和复制；同事目录的手工提交也不能被自动推送带上去。

每轮先提交本地资料，再获取并合并远程指定分支，最后推送。已有仓库的源与设置不一致时停止，不自动覆盖 Git 源。任务根 `AGENTS.md` 和 `TASK-CONTEXT.md` 的系统管理区列出本地实际目录、完整路径和权限；检出或合并后更新所有关联任务，包括归档任务。后续推送失败时也更新本地清单；自定义说明或写入失败会提示，可通过“刷新资料”单独重试说明更新，不重复同步。

未保存资料或文件操作尚未完成时会延后同步。存在 Git 冲突、未完成合并、认证或仓库身份问题时自动同步暂停；通过“打开仓库”使用 Git 或 IDE 解决冲突并提交，再回到设置中重新检查。SW 不会强推、强制重置、清理文件或自动放弃合并；网络故障在下一周期重试。

同页“默认展开目录层级”默认是 2，0 表示全部折叠。修改后当前资料树立即重新应用，其他任务下次打开时应用；之后继续保留手工展开和收起状态。
